## 壮丽鞘翅（Enigmatic Elytra）1.7.10 移植补齐

关键结论：1.7.10 侧鞘翅的**一切**实现都在 Et Futurum Requiem（Backlytra 移植）里 —— 起跳（`MixinEntityPlayerSP`）、飞行物理（`MixinEntityLivingBase`）、披风隐藏与每 20 tick 耐久损耗（`MixinEntityPlayer#tickElytra`）、翅膀渲染（`ClientEventHandler#renderPlayerSetArmour` + `LayerBetterElytra`）全部以 `ItemArmorElytra#getElytra(entity)` 为唯一判据，且 `tickElytra` 每 tick 会在判据为 null 时**强制清掉**飞行 flag。所以移植前那份「motionY 钳制」只是慢速下落，不是滑翔。

改动：

- `mixin/MixinEtFuturumElytra`：`@Inject` 到 `ItemArmorElytra.getElytra` 的 RETURN，原值为 null 时返回饰品栏/胸甲栏里的壮丽鞘翅（未损坏）。一次钩子即拿下起飞判定来源、飞行物理、披风隐藏、每 20 tick 耐久损耗、烟花助推兼容。
- `mixin/MixinEtFuturumElytraTakeoff`：起飞包 `StartElytraFlyingHandler#onMessage` 里有 `instanceof ItemArmorElytra` 硬校验（flag 只能在这里被打开，`tickElytra` 只会维持），所以对「解析结果是本物品」的情况在 HEAD 复刻同一套判定并 `etfu$setElytraFlying(true)`，其余情况放行原逻辑。
- `items/EnigmaticElytra`：删掉慢速下落，新增 `boostPlayer`（1:1 复刻 1.20 的 look 向量冲量 0.1 / 1.5 / 0.5）、`isFallFlying`（走 API `IElytraPlayer`）、`getActiveElytra`（Et Futurum 自己的鞘翅优先）。
- `client/EnigmaticElytraHandler`：ClientTickEvent 里检测「按住跳跃 + 正在滑翔」→ 本地加速 + 状态变化时发包 `PacketUpdateElytraBoosting`（包本身早已移植好），并按同步来的 `TransientPlayerData` 给所有推进中的玩家撒粒子。1.7.10 没有 `dragonbreath` 粒子，改用 `witchMagic`。
- `EnigmaticEventHandler#onPlayerTick`：服务端复刻 1.20 的推进 tick，推进期间每 5 tick 扣 1 耐久。
- `client/renderers/EnigmaticElytraLayer` + `mixin/MixinEtFuturumElytraLayer`：Et Futurum 那层在有披风时会绑玩家披风贴图，故对本物品取消，改在 `RenderPlayerEvent.Specials.Post` 用它的 `ModelElytra` + mod 的 `textures/models/misc/elytra.png` 自己画。

验证：`./gradlew build` 通过（含 checkstyle）；`runClient` 启动日志确认两个 mixin 已注入（`Mixing ... into ganymedes01.etfuturum.items.equipment.ItemArmorElytra` / `...network.StartElytraFlyingHandler`）。起飞→滑翔→加速→落地的整链和翅膀贴图未做游戏内实测（客户端无输入自动化）；`MixinEtFuturumElytraLayer` 的目标类只在渲染玩家时加载，未验证。

## 被诅咒者的寻路指针（Soul Compass）移植补齐

对照结论：服务端链路完全一致 —— `SoulArchive.findNearest` / `SuperpositionHandler.updateSoulCompass`（每 10 tick）→ `PacketUpdateCompass` → 客户端 `SoulCompass.setNearestCrystal`。**缺的是指针动画**：1.20 用 `ItemProperties.register("angle")` + `models/item/soul_compass.json` 的 33 条 override 在 `compass_00..31` 之间切模型；`items/SoulCompass#getCompassAngle` 在移植版里根本没有消费者（死代码），图标固定是 `compass_16`，指针不会转。

实现（`items/SoulCompass.java`）：

- `registerIcons` 注册 32 帧 `enigmaticlegacy:item/compass_%02d`（item atlas → `textures/items/item/compass_XX.png`，文件本来就齐全），`itemIcon` 取 `compass_16`。
- 重写 `getIconIndex(ItemStack)` 与 `getIcon(ItemStack, int)` → `frameIcon()`。前者覆盖 GUI/掉落物（`ItemStack.getIconIndex`），后者覆盖第一/第三人称手持（Forge 的 `getIcon(stack, pass, player, ...)` 默认转调它）。
- 帧公式：`(floor(angle * 32 + 0.5) + 16) & 31`。1.20 的 override 从 1/64 起、步长 1/32，所以 frame16 首尾各占半格；已用脚本按全部 33 个 bucket 取中点核对，0 处不符。
- 补上 1.20 property function 里那三条门控（原来 `getCompassAngle` 里没有）：非受咒者 / 该 stack 不在背包（`hasExactStack`）/ 玩家就站在目标水晶上 → 走随机角。灵魂沙峡谷那条 1.7.10 无对应生物群系，跳过。

验证：`./gradlew build` 通过；`runClient` 启动后 32 张帧贴图全部注册成功（`MISSING_ICON` 只有 Et Futurum 的 bubble_column，`compass_` 缺失计数 0），无异常。指针实际观感未做游戏内验证。
