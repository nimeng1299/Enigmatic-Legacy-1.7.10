## 迷人徽章（Charming Insignia / `insignia`）1.20 → 1.7.10 对比补齐

用户上一轮问的飞升护符已收尾（见 11-07 日志）。本轮对照只读的 1.20 源码：徽章效果分散在
`items/Insignia`、`MixinEntityRenderer`、`SuperpositionHandler#renderInsigniaNameplate`、
`MixinItemStack`、`RenderNameTagEvent` 处理器五处；1.7.10 除注册表外 `INSIGNIA` 零引用，
等于整块没实现。

实现（4 项 + 1 项格式修复）：
1. **铭牌替换**：`MixinRendererLivingEntity` 用 `@Redirect` 拦截 `passSpecialRender` 里的
   `func_145748_c_()`（潜行/非潜行共用一处），返回反序列化的 `IChatComponent`，保留颜色样式。
2. **真名小字**：`@Inject` `func_96449_a` TAIL，新增 `client/renderers/InsigniaNameplateRenderer`
   按 1.20 参数绘制（0.4x、下移 10px、无背景板、64 格限制）；`canSeeTrueName` 且存在雕刻才画。
3. **自己可见**：`@Inject` `func_110813_b` HEAD，戴徽章 + `tagDisplayEnabled` 时返回 true
   （1.7.10 原版无条件排除本地玩家，对应 1.20 的 `RenderNameTagEvent.ALLOW`）。
4. **物品名不被雕刻覆盖**：新建 `MixinItemStack`，徽章的 `getDisplayName` 返回物品名、
   `hasDisplayName` 返回 false（对应 1.20 `getHoverName` / `hasCustomHoverName`）。
5. **tooltip 格式**：`Insignia` 新增 `getCustomNameComponent`，`getCustomName` 改用
   `getFormattedText()`，建筑师墨水的颜色不再丢失（原实现用 `getUnformattedTextForChat()`）。

关键结论 / 平台限制：
- 1.20 的 `+1 charm 槽`（`CuriosApi.addSlotModifier("charm", 1)`）在 1.7.10 无法等价实现：
  Baubles 槽位由 `BaubleExpandedSlots` **全局静态**分配，无按玩家增删槽位的 API，
  自建槽位系统被 AGENTS.md 禁止。归入清单第 10 条的平台差异。
- 1.7.10 玩家渲染走 `RendererLivingEntity`（`RenderPlayer` 不经过 `RenderLiving`），所以注入点
  必须选 `RendererLivingEntity`，而不是 `RenderLiving`。
- `passSpecialRender` = `func_77033_b`；`func_96449_a` / `func_110813_b` / `func_147906_a` 无
  MCP 可读名，直接用 srg 名作 `method` 值即可；`ItemStack.getDisplayName` → `func_82833_r`、
  `hasDisplayName` → `func_82837_s`（MCP 名写法由注解处理器映射）。

改动文件：`items/Insignia`、`mixin/MixinItemStack`（新）、`mixin/MixinRendererLivingEntity`（新）、
`client/renderers/InsigniaNameplateRenderer`（新）、`mixins.enigmaticlegacy.json`

## 莫测之眼（Enigmatic Eye / `enigmatic_eye`）注册核对

用户怀疑「休眠之眼 / 莫测之眼」物品注册搞反了。逐项比对 1.20（`E:\code\Enigmatic-Legacy-1.20.x`，只读）：

- **注册本身没反**：两边都是单物品 `enigmatic_eye`，状态由 NBT `IsDormant`（默认 true）决定，
  激活后 `IsDormant:0`；`getName` 分支、tooltip 分支、`use()` 激活流程、模型 JSON、patchouli 条目、
  5 个语种 lang 全部一致。只要不额外写 `.name` 后缀，1.20 的 `item.enigmaticlegacy.enigmatic_eye_dormant`
  /`..._active` 就是「休眠之眼 / 莫测之眼」。
- **真反的是图标**：1.20 靠 `models/item/enigmatic_eye.json` 的 `layer0 = item/enigmatic_eye_dormant`
  默认显示休眠外观，predicate `enigmaticlegacy:enigmatic_eye_activated` 到 1.0 才切 `enigmatic_eye_active`
  （`item/enigmatic_eye.png` 是 4 帧动画的觉醒眼）。1.7.10 走 `ItemBase.registerIcons` →
  `getIconName()` = `enigmatic_eye`，直接用觉醒贴图且无休眠分支，所以新拿到的休眠之眼长得像莫测之眼。
- 顺带修复：`getName` 里翻译键少了 `.name` 后缀。本仓库 lang 的 111 个物品名全部是
  `item.enigmaticlegacy.xxx.name`，而 `Component.translatable` 直接构造 `ChatComponentTranslation(key)`，
  缺后缀会原样显示键名。

实现（`items/EnigmaticEye.java`）：`registerIcons` 额外注册 `item/enigmatic_eye_dormant`、`_1`、`_2`，
`itemIcon` 复用为觉醒图标；`getIconIndex`/`getIcon(stack, pass)` 统一走 `iconFor(stack)`——
非休眠 → 觉醒；休眠时 `ActivationAnimation > 2` → `_1`、`> -1` → `_2`、否则 → dormant，
与 1.20 `registerVariants` 的 0.4/0.8/1.0 及 overrides 阈值（0.33/0.66/1.0）对应。

验证：`./gradlew spotlessApply build` 通过。**未做**：`runClient` 实测激活动画四帧切换。

遗留（未动）：该类的 `getAttributeModifiers` 仍是空壳 `if (!this.isDormant(stack)) {}`，
1.20 在觉醒后给 `+1 charm 槽`（Curios，1.7.10 平台无等价物，参见上面徽章条目）与
`ForgeMod.BLOCK_REACH +3`（1.7.10 应为 `EntityPlayer.getAttributeMap` 的
`PlayerControllerMP.getBlockReachDistance` 路径，1.7.10 无 reach 属性）。需要单独评估。

## 休眠之眼（Architect Eye）首次战利品箱奖励 — 已实现

用户要求「休眠之眼出现在你打开的第一个战利品箱里」，即 1.20 `SpecialLootModifier`
的 Architect Eye 分支（持久标记 `LootedArchitectEye`，条件为 `minecraft:chests/` 战利品表）。

1.7.10 没有战利品表，箱子内容在结构生成时就滚好了，所以拆成「生成时打标记 + 开箱时注入」两步：

1. `mixin/MixinWeightedRandomChestContent` 在 `generateChestContents` RETURN 新增
   `SpecialLootModifier#markLootChest(inventory)`（与已有的启示录书注入同一个注入点，拆成两个
   `@Inject`，互不依赖对方的早退逻辑）。这是「箱子战利品表 id 以 minecraft:chests/ 开头」的等价判据。
2. 新增 `api/quack/ILootChest` + `mixin/MixinTileEntityChest`：`TileEntityChest` 实现该接口，
   `@Unique` 字段 + `readFromNBT`/`writeToNBT` RETURN 注入读写 NBT 标记 `EnigmaticLootChest`。
   **必须持久化**：1.7.10 方块实体不会保存自己不写入的 NBT，区块存盘后标记会丢。
3. `SpecialLootModifier#onChestOpened` 拆成 `grantArchitectEye` + `grantAstralFruit` 两个分支
   （外层仍只判 `TileEntityChest` + world 非空），眼放进随机空位，成功后写持久标记。

行为差异（相对 1.20）：标记只在眼真正放入后消费（满格不浪费机会）；同一箱子被多个玩家先后
打开时每人各得一次（1.20 只有首个开箱者）；末影箱/漏斗/发射器不计。

验证：
- `./gradlew build` 通过。
- `runServer` + `-Dmixin.debug.export=true`：`run/server/.mixin.out` 里 `TileEntityChest`
  已 `implements ILootChest`，`readFromNBT`/`writeToNBT` 尾部均调用注入的 handler；
  `WeightedRandomChestContent` 尾部调用 `markLootChest`。
- 临时自检（已删除，`EnigmaticLegacy#serverStarting` 调用 `debugSelfTest`）实测：
  `marked=true items=5 persisted=true copyItems=5 eyeDormant=true eyeEnabled=true`
  —— 结构箱打标记、NBT 往返、新物品默认为休眠、配置开启全部 OK。
- **未做**：进服务器/单机实际开箱验证（需要玩家走到地牢）。
